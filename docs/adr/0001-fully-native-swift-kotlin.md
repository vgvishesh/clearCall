# 0001 — Fully native apps (Swift/SwiftUI, Kotlin/Compose) on libwebrtc

- Status: Deferred (V1 is web-only, see 0003)
- Date: 2026-10-11

## Context
Call quality is decided in the media layer: audio session/route handling, echo cancellation, codec selection, hardware encoders, CallKit/Telecom integration, background execution. All of it is platform-specific. The UI itself is a contact list and a call screen.

## Decision
Two native apps sharing a protocol contract (`protocol/`) and E2E flows (`quality/e2e/`), both using libwebrtc prebuilt `webrtc-sdk` builds. iOS project generated by XcodeGen.

## Alternatives considered
- Flutter / React Native + WebRTC plugin: faster UI, but adds a bridge between us and the audio/video pipeline, lags upstream WebRTC, and complicates CallKit/ConnectionService. Rejected — UI is not where the effort goes.
- Kotlin Multiplatform for shared call logic: viable later for the call state machine; not worth the build complexity on day one.
- Building our own media engine: no.

## Consequences
Feature work is done twice; mitigated by agents per platform working from one plan, and a parity reviewer. Reverse cost: high (rewrite).
